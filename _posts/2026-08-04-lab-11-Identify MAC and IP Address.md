## Overview

In this lab, I explored how Ethernet frames and IPv4 packets move through a network. Rather than configuring devices, this activity focused on observing Packet Data Units (PDUs) as they traveled between hosts on both local and remote networks. Using Packet Tracer's **Simulation Mode**, I captured each step of the communication process to examine how MAC addresses and IP addresses change—or remain unchanged—as packets traverse switches, hubs, routers, and wireless access points.

---

## Objectives

- Observe local network communication between hosts on the same subnet.
- Observe communication between hosts on different IP networks.
- Compare Layer 2 (MAC) addressing with Layer 3 (IP) addressing.
- Identify how switches, hubs, routers, and wireless access points handle Ethernet frames.

---

## Network Topology

The topology consisted of two IPv4 networks connected by a router.

- **172.16.31.0/24**
  - Switch
  - Hub
  - Four PCs

- **10.10.10.0/24**
  - Switch
  - Wireless Access Point
  - Two wireless laptops

The router connected the two networks and served as the default gateway for each subnet.

## Part 1 - Local Network Communication

The first portion of the lab examined communication between devices located on the same subnet.

The following tests were completed:

- 172.16.31.5 → 172.16.31.2
- 172.16.31.3 → 172.16.31.2
- 172.16.31.5 → 172.16.31.4

Packet Tracer Simulation Mode allowed each frame to be inspected as it moved across the network.

## Initial Ethernet Frame

The outbound PDU from **172.16.31.5** showed the original Ethernet and IP addressing before the frame left the computer.

Observations:

- Source MAC: 00D0.D311.C788
- Destination MAC: 000C.85CC.1DA7
- Source IP: 172.16.31.5
- Destination IP: 172.16.31.2

![Outbound PDU generated by 172.16.31.5.]({{ site.baseurl }}/assets/images/lab11/outboundPDU.png)

---

## Switch Behavior

When the frame reached the switch, neither the Ethernet header nor the IP packet changed.

The switch simply examined the destination MAC address, consulted its MAC address table, and forwarded the frame toward the correct destination port.

![Outbound PDU observed at the switch.]({{ site.baseurl }}/assets/images/lab11/outboundPDUatswitch.png)

---

## Hub Behavior

Unlike the switch, the hub had no knowledge of MAC addresses.

Instead, it repeated the incoming frame to every connected device.

Both attached PCs received the frame, but only the intended destination accepted it. The remaining device discarded the frame after determining the destination MAC address did not match its own.

![Outbound PDU observed at the hub.]({{ site.baseurl }}/assets/images/lab11/outboundPDUatHub.png)

---

## Echo Reply

Once the destination computer received the ICMP Echo Request, it generated an ICMP Echo Reply.

During the reply:

- Source and destination MAC addresses reversed.
- Source and destination IP addresses reversed.
- The communication path remained unchanged.

![Outbound PDU generated by the destination host.]({{ site.baseurl }}/assets/images/lab11/outboundPDUatDestination.png)

## Part 2 - Remote Network Communication

The second portion of the lab examined communication between different IP networks.

Test performed:

- 172.16.31.5 → 10.10.10.2

Unlike communication within a single subnet, the destination host was located on another network. Instead of sending the Ethernet frame directly to the destination device, the PC addressed the frame to its default gateway (the router).

The router removed the original Ethernet frame, examined the IP packet, and created a completely new Ethernet frame for the next network segment.

Key observations included:

- Source and destination IP addresses remained unchanged throughout the trip.
- Source and destination MAC addresses changed when the packet crossed the router.
- The router served as the boundary between the two Layer 2 networks.

---

## Wireless Access Point Behavior

After the router forwarded the packet onto the 10.10.10.0/24 network, the switch delivered it to the wireless access point.

The access point transmitted the frame over the wireless medium.

Both wireless laptops received the transmission because Wi-Fi is a shared medium; however, only **10.10.10.2** processed the frame because its MAC address matched the destination MAC address. The second laptop discarded the frame.

![Wireless transmission observed from the access point.]({{ site.baseurl }}/assets/images/lab11/wifi.png)

---

## Key Observations

## Switch

- Uses a MAC address table.
- Forwards frames only toward the correct destination.
- Does not modify Ethernet or IP headers while forwarding.

## Hub

- Does not learn MAC addresses.
- Repeats every frame to every connected device.
- Relies on end devices to determine whether to accept or discard frames.

## Router

- Connects different IP networks.
- Removes the original Ethernet frame.
- Creates a new Ethernet frame using the MAC addresses of the next network.
- Leaves the source and destination IP addresses unchanged.

## Wireless Access Point

- Bridges wired Ethernet and wireless communications.
- Transmits wireless frames over a shared medium.
- All wireless clients receive the transmission, but only the intended recipient processes the frame.

---

## Reflection

This lab clearly demonstrated the relationship between Layer 2 and Layer 3 addressing.

Within a single subnet, communication relied entirely on MAC addresses to deliver Ethernet frames between hosts. The switch forwarded frames based on its MAC address table, while the hub simply repeated every frame without examining any addressing information.

Communication between different IP networks introduced the router. Although the Ethernet frame changed when it crossed the router, the IP packet remained intact. This demonstrated that MAC addresses are local to each network segment, while IP addresses identify the original sender and final destination across the entire route.

The wireless access point also highlighted how wireless communication differs from switched Ethernet. Every nearby wireless device received the transmitted frame, but only the intended recipient accepted and processed it.

---

## Conclusion

This Packet Tracer activity reinforced several fundamental networking concepts.

I observed how switches intelligently forward traffic using MAC addresses, how hubs simply repeat incoming frames, how routers create new Layer 2 frames while preserving Layer 3 addressing, and how wireless access points bridge wired and wireless communication.

Following individual PDUs through the network provided a much clearer understanding of how Ethernet frames and IP packets interact during both local and remote communication. The exercise also demonstrated why routers are required for communication between different IP networks and why MAC addresses change at each routed hop while IP addresses remain consistent from source to destination.
